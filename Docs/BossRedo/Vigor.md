# 神威·断罪刃（Vigor）重做设计文档 — Boss 重做工程 V3

> 单元：`Celestias/Boss/Vigors/`（后月球领主天界 Boss，约 200 万 HP）
> 题材：天庭刑官——燃金焰的巨灵神之手握断罪斧钺（贴图：金焰巨手 + 斧钺；弹幕贴图：符文日轮球 / 新月符刃）。
> 配色语言：符金 RuneGold(220,180,60) / 符蓝 RuneBlue(80,140,255) / 白金 WhiteGold(255,245,200) / 铁灰天幕。红色仅致命预警（TelegraphColors.Lethal）。

## 1. 现状诊断

以 choreography skill 七大本能与失败模式清单为透镜：

1. **巨手持斧却从不挥斧（本能1/3 双违反，最高杠杆问题）**。全部"斩击"只是生成弹幕，`NPC.rotation = velocity.X * 0.025f` —— 身体语言为零：没有 backswing→strike→recovery 挥舞波形，没有发射后坐，没有余摆。Boss 读起来是"会喷弹幕的漂浮贴图"。
2. **冲刺无收束-爆发语法（本能2/4 违反）**。`velocity = dir * 40` 一帧设定后匀速漂完，无 reel-back 反向蓄势、无预警线、无硬刹（仅 ×0.93 缓收），粒子从头喷到尾没有"爆发前静默"。
3. **符文能量球机制浪费**。`RunicEnergyOrbs` 仅两种用法：直线飞弹、原地延时雷。没有环绕护体、没有蓄能可读性、没有齐射/连锁——符环本应是这个"审判程序"Boss 的机制主轴。
4. **节奏平坦（本能5 违反）**。攻击选择 `Main.rand.Next(n)` 纯随机可连抽同招；`EndAttackWithCombo` 的"连击"只是再抽一次，没有编排的强弱交替；三阶段强度差主要靠数值不靠内容解锁。
5. **入场单薄、死亡缺失（本能7 违反）**。入场是"上方淡入下降 140 帧"；死亡只有 `OnKill` 一声震动 + 一把粒子——200 万血的天庭刑官一秒消失。
6. **可读性缺口**。符印直接落在玩家脚下（预告不足）；符环齐射类攻击（Vortex）从屏外 500px 全向收束，玩家无法从 Boss 姿态读出招式来源；接触伤害无视觉对齐（悬停时贴身也掉血）。
7. **已有可保留的 V2 资产**：判决光束（BeamGrad）、符印地纹（ArenaRunic）、处决泛光（RadialBloom）、hitstop 定格、`VigorVerdictSystem` 屏幕演出层、`VigorSky` 金纹天幕——质量尚可，保留并挂接到新编排上。状态机无死路（各态有超时出口），多人同步骨架健全（ai[]/SendExtraAI）。

结论：**全面重做 AI 编排 + 符环机制主轴 + 三大演出节拍**，视觉在 V2 资产之上加两个专属着色器。

## 2. 设计主题与幻想感

**“天条刑律的执行程序”**。神威不是野兽，是刑官——审判是程序化、仪式化的：

> 宣读罪状（符环逐颗点亮，音高逐步上升）→ 合议（法阵旋转收束）→ **宣判**（一拍静默，万籁俱寂）→ 行刑（斧落 / 齐射 / 连锁引爆）→ 阖卷（收招余摆）。

玩家体验 = "站在天庭法庭被审"：一切大伤害都有可读的"庭审进度条"——**断罪符环**上点亮的球数就是下一波攻击的规模。玩家永远能"读出"充能程度，也永远有干预手段（打掉护体球 = 削减齐射弹药）。

**核心机制闭环：断罪符环（12 颗符文能量球）**
- **护体（诚实护盾）**：符环环绕 Boss 公转，点亮的球替 Boss 承伤——每吸收一次命中熄灭一颗（该次伤害 -45%）。球亮=有盾，球灭=真伤窗口，完全诚实。
- **蓄势（宣读罪状）**：大招前符环逐颗点亮（每颗一声 tick、音高上升），点亮数 = 齐射数。
- **行刑（齐射/连锁）**：点满后一拍静默，按点亮顺序连珠齐射；或布阵为大环后链式引爆。
- **闭环**：护体阶段被打掉的球，齐射时就少射几颗——拆盾即减压，攻防一体。

## 3. 阶段结构与血量断点

血量断点保持 100%–60%–30%（`Phase2Threshold`/`Phase3Threshold` 为 `VigorSky` 所依赖，不动）。

| 阶段 | 血量 | 主题 | 内容解锁 |
|---|---|---|---|
| 一阶段「听讼」 | 100%→60% | 教学式压迫：挥斩语法、符印预告、冲锋判决 | 无符环；4 招 |
| 二阶段「宣判」 | 60%→30% | **断罪符环登场**：护体/齐射/囚阵三用法 | 5 招（2 新）|
| 三阶段「天刑」 | 30%→0% | 全解锁 + 处决级演出：四极刑架、无间斩舞、天罚 | 4 招（强化版）|
| 死亡「阖卷」 | 0 | ~5 秒死亡演出（beep 加速→静默→白金闪→溶解→终爆）| — |

攻击选择改为**手写轮替表**（PACING §2）：每阶段一个循环数组，保证强弱交替、绝不连抽同招；表索引 `attackCycleIndex` 走 `SendExtraAI` 同步。

## 5. 入场 / 换阶段 / 死亡三大演出脚本

**入场「开庭」（~170 帧）**——菜单：法阵开庭 → 砸落 → 静止凝视
- 0–40：玩家上方 340px 处凭空展开金色断罪法阵（VigorRunicSigil 从 0 旋出，Sky 同步压暗），无声，只有低鸣。
- 40–96：法阵增大加速旋转，符文粒子从 400px 外收束（converging streaks + 切向漩涡），72% 处密度 hard-cut。
- 96–110：**静默拍**——粒子清空，法阵骤缩 40% 并 cos 颤动。
- 110：Boss 从法阵中砸落而出（120px/f × 10 帧），落定 impact：shake 12、Roar、金环尘爆、8 向符刃 + 4 角符印（保留原意）。
- 110–168：落定后 58 帧**静止凝视**（menace is stillness），只有金焰上飘与斧刃微光 → 一声怒吼 → 开战。

**换阶段 2「宣判庭启」（~150 帧，dontTakeDamage）**
- 0–50：Boss 收束静默、巨斧上举过顶（backswing 语法反用），全场敌意弹幕清除。
- 50–110：天幕金脉冲，12 颗符文能量球从天幕列队降位成环（每 4 帧一颗、音高上升 tick），首次展示"点亮"语法。
- 110：斧落一斩宣判——shake 11、12 向刃波、处决泛光。
- 110–150：符环开始公转，恢复可伤，进二阶段轮替。

**换阶段 3「天刑加冕」（~130 帧，dontTakeDamage）**
- 0–60：符环全部强制点亮（快速 tick 序列），收束到斧刃上——斧刃白金过曝。
- 60–72：**白金裁决闪**（VigorExecutionFlash 低强度 10 帧首秀，走全屏名额）。
- 72：16 向刃波 + 16 向符球双层爆发 + 12 角符印，天幕白金化（Sky 三阶段配色已有）。
- 72–130：余韵恢复，进三阶段轮替。

**死亡「阖卷」（~300 帧，CheckDead 拦截）**
- 0：`CheckDead` → 进 Death 态：life=1、无敌、全场清弹、天幕转暗（Sky 读 Boss 死亡标量）。
- 0–50：Boss 硬刹定格，符环失控（轨道抖动、乱闪），斧焰忽明忽暗。
- 50–150：**beep 加速序列**（间隔 40→6 帧递减 12 步、音高递升），每声 beep 熄爆一颗符环球 + 小震；Boss 缓慢上浮、旋转失稳（阻尼余摆）。
- 150–180：**全静默**——粒子清空、天幕最暗、Boss 收缩 8% cos 微颤。
- 180：**impact frame**——VigorExecutionFlash 满强度 14 帧（黑白高对比 + 竖向斩线），Item14 重响 + shake 19（全场唯一一次）。
- 180–260：斧与手贴图 DissolveBurn 溶解（共享着色器 s1=噪声），金焰残烬缓落。
- 260–300：中心白金终爆（RadialBloom 满强 + 40 向金尘）→ 服务器执行真死 → `OnKill` 掉落/downed 标记照旧。

## 6. 视觉技术方案

**新建专属着色器（ps_3_0，Vigor 前缀，程序化自包含噪声，ModContent.Request 静态缓存，不注册 ACMShaders）：**
1. `VigorRunicSigil.fx` — 断罪法阵/符环刻度盘：多重旋转符环（内外反向）+ **充能刻度扇区**（uCharge 0~1 沿圆周依次点亮的格块，uSegments 可配）+ 角向辐条 + 边缘警戒环 + 展开动画（uProgress）。载体 SoftGlow quad 世界空间绘制。用于：入场开庭法阵、符环齐射充能读法、符印锁狱落点、四极封印中央阵、天罚充能、死亡失控阵。
2. `VigorExecutionFlash.fx` — 处决裁决闪（全屏后处理，s0=screenTarget）：黑白高对比矩阵 + 中心竖向斩线过曝 + 边缘暗角，uIntensity 驱动。仅两处使用：换阶段 3 首秀（低强度）、死亡 impact frame（满强度）；一律走 `ACMShaders.RequestFullscreenSlot()` 名额契约 + `MythologyConfig` 开关。

**复用共享件**：BeamGrad（判决光束/冲刺暗线/囚阵连线）、ArenaRunic（符印地纹，保留 V2）、RadialBloom（处决泛光，保留）、ElementalScreenTint（罪名色金幕，保留）、DissolveBurn（死亡溶解）、ACMAsset.SoftGlow/BlankStar/Sparkle、`ACMShaders.NoiseTexture`。

**挥斧身体语言（代码侧）**：`swing` 视觉状态（timer+dir，各端确定性）驱动 `NPC.rotation`：quad in-out 到 -0.91rad（anticipation）→ poly(20) ease-out 到 +1.68rad（strike）→ quintic 回正（recovery）；strike act 期间才开启残影 + 斧尖 BeamGrad 弧光 + 接触伤害；每次发射符刃 Boss 反向 recoil；砸落后 rotation 阻尼余摆（`angVel -= angVel*0.08 + …`）。

## 7. 性能与多人预算

- **弹幕上限**：符环常驻 12；齐射在场 ≤12；囚阵节点 ≤14；刃波单波 ≤16。同屏敌意弹幕峰值 ~45，低于既有 Vortex 招（36+ 持续刷）量级。
- **绘制**：`DrawSigil` 每帧 ≤3 实例（各一次 End/Begin Immediate）；DrawBeam ≤8 条（复用既有数组）；全屏后处理同帧 ≤1 且 <1% 战斗时长激活；无每帧 new 纹理/Effect（静态 `Asset<Effect>` 缓存 + 共享噪声）。
- **多人**：AI 决策只依赖 `npc.ai[]`/同步字段（`attackCycleIndex`/`wardCharges` 等走 SendExtraAI），状态切换 `netUpdate = true`；弹幕/符环生成全部 `Main.netMode != NetmodeID.MultiplayerClient` 守卫；符环球位置由 (Boss index + 槽位角) 确定性计算不需逐帧同步；hitstop/泛光/法阵等演出字段各端由同步状态确定性驱动，服务器无绘制。
- **掉落/进度不回退**：`ModifyNPCLoot`/`BossLoot`/`OnKill`（downedVigor + 震动）/召唤方式/BossChecklist 集成完全保留。
